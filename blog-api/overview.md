## Что такое AI Factory?

**AI Factory** — это npm-пакет и система навыков, которая автоматизирует настройку контекста для AI-агентов в ваших проектах.

### Три главных компонента:

1. **CLI-инструмент** (`ai-factory init/update/upgrade`) — устанавливает навыки и настраивает MCP
2. **Встроенные навыки** (22 навыка с префиксом `aif-`) — команды для spec-driven разработки
3. **Spec-driven рабочий процесс** — структурированный подход: план → реализация → коммит

### Простыми словами:

Вместо того чтобы вручную объяснять AI-агенту (Claude Code, Cursor, Qwen Code и др.) структуру вашего проекта, AI Factory делает это автоматически. Вы запускаете `ai-factory init`, выбираете свой AI-агент, и всё настраивается само.

## Зачем это нужно?

### Проблема:
- Настройка AI-агентов для работы с проектом занимает много времени
- Нужно объяснять контекст, правила, архитектуру
- Каждый агент требует своей конфигурации
- Промпты и навыки нужно создавать вручную

### Решение AI Factory:
- **Zero configuration** — сам анализирует проект и устанавливает нужные навыки
- **Лучшие практики встроены** — логирование, коммиты, код-ревью по стандартам
- **Spec-driven разработка** — AI следует плану, а не хаотично исследует
- **Работает со всеми агентами** — 15+ поддерживаемых AI-агентов
- **Автоматическая настройка MCP** — конфигурирует серверы для работы с GitHub, БД, файлами

## Основные концепции

### 1. Skills (Навыки)

Навыки — это markdown-файлы, которые говорят AI-агенту, как выполнять определённые задачи. Например:
- `/aif-plan` — создать план для фичи
- `/aif-implement` — реализовать план
- `/aif-fix` — быстро исправить баг

**Расположение:**
- **В пакете:** `skills/` — источник истины
- **В проекте агента:** `.claude/skills/`, `.qwen/skills/`, `.cursor/skills/` и т.д.

### 2. Spec-Driven Workflow (Разработка по спецификации)

Вместо хаотичной разработки AI Factory заставляет AI следовать чёткому плану:

```
/aif-explore → /aif-plan → /aif-improve → /aif-implement → /aif-commit
```

Каждый шаг создаёт файлы в `.ai-factory/`, которые читаются следующим шагом.

### 3. Artifact Ownership (Владеление артефактами)

Каждая команда отвечает только за свои файлы, чтобы избежать конфликтов:

| Артефакт | Создаёт |
|----------|---------|
| `DESCRIPTION.md` | `/aif` |
| `ARCHITECTURE.md` | `/aif-architecture` |
| `PLAN.md` | `/aif-plan` |
| `ROADMAP.md` | `/aif-roadmap` |
| `RULES.md` | `/aif-rules` |

### 4. MCP (Model Context Protocol)

Протокол для подключения внешних сервисов (GitHub, PostgreSQL, файловая система). AI Factory автоматически настраивает MCP для поддерживаемых агентов.

## Как это работает

### Инициализация проекта (`ai-factory init`)

```
1. Пользователь запускает: ai-factory init
2. CLI задаёт вопросы:
   - Какой AI-агент вы используете?
   - Какие навыки установить?
   - Настроить MCP?
3. Анализирует проект (ищет package.json, Cargo.toml, etc.)
4. Копирует навыки в нужные директории агента
5. Генерирует .ai-factory/DESCRIPTION.md
6. (Опционально) Настраивает MCP серверы
```

### Рабочий процесс в AI-агенте

После инициализации открываете AI-агент и используете slash-команды:

```
/aif                    # Настройка контекста (если не запускали init)
/aif-explore <тема>     # Исследование кодовой базы
/aif-grounded <вопрос>  # Проверка фактов о проекте
/aif-plan <фича>        # Создание плана
/aif-improve            # Улучшение плана
/aif-implement          # Выполнение плана
/aif-fix <баг>          # Быстрая фиксация
/aif-commit             # Создание коммита
/aif-review             # Код-ревью
/aif-loop <цель>        # Итеративный цикл с проверкой качества
/aif-evolve             # Самоулучшение навыков
```

## Рабочий процесс

### Полный цикл разработки фичи:

```
1. /aif-explore "Добавить OAuth авторизацию"
   ↓ Исследует кодовую базу, создаёт RESEARCH.md

2. /aif-grounded "Есть ли уже поддержка OAuth?"
   ↓ Проверяет факты, даёт точный ответ

3. /aif-plan "Добавить OAuth авторизацию"
   ↓ Создаёт ветку, генерирует PLAN.md с задачами

4. /aif-improve (опционально)
   ↓ Углубляет план, добавляет детали

5. /aif-implement
   ↓ Выполняет задачи по одной
   ↓ Обновляет DESCRIPTION.md при изменениях
   ↓ Отмечает выполненные milestone в ROADMAP.md
   ↓ Предлагает создать коммит на чекпоинтах

6. /aif-commit
   ↓ Создаёт коммит с conventional commit message

7. /aif-review
   ↓ Проверяет код на качество и безопасность

8. /aif-evolve (периодически)
   ↓ Анализирует паттерны, улучшает навыки
```

### Баг-фикс (быстрый путь):

```
/aif-fix "TypeError: Cannot read property 'name'"
   ↓ Исследует код
   ↓ Находит причину
   ↓ Исправляет
   ↓ Предлагает тест
   ↓ Создаёт патч для self-improvement
```

## Команды CLI

### Основные команды:

```bash
# Инициализация проекта
ai-factory init

# Обновление навыков
ai-factory update

# Миграция с v1 на v2
ai-factory upgrade

# Управление расширениями
ai-factory extension add <source>
ai-factory extension remove <name>
ai-factory extension list
```

### Флаги:

```bash
ai-factory update --force    # Полная переустановка навыков
ai-factory init --no-mcp    # Пропустить настройку MCP
```

```
│   ├── plans/
│   │   └── feature-oauth.md    # Планы для веток (full mode)
│   ├── patches/
│   │   └── 2024-04-01-fix.md   # Патчи self-improvement
│   ├── skill-context/
│   │   └── aif-plan/           # Специфичные для проекта overrides
│   └── evolutions/
│       └── 2024-04-01.md       # Логи эволюции навыков
│
├── .claude/                    # Для Claude Code
│   └── skills/
│       ├── aif/
│       ├── aif-plan/
│       └── ...
│
└── .qwen/                      # Для Qwen Code
    └── skills/
        ├── aif/
        ├── aif-plan/
        └── ...
```

### DESCRIPTION.md — Главный файл

Содержит спецификацию проекта:
- Название и описание
- Стек технологий
- Структура проекта
- Ключевые компоненты
- Особенности и ограничения

Все навыки читают этот файл для понимания контекста.

## Безопасность

AI Factory имеет двухуровневую систему безопасности:

1. **Сканирование навыков** — проверка внешних навыков перед установкой
2. **Контекстные ворота** — проверка архитектуры и правил при верификации
